# Автоматическая установка на новой аренде

Скрипт `scripts/rent-setup.sh` устанавливает выбранный сервис LUSTIFY V10 Turbo
FP8 с адаптером редактирования и запускает API и GPU-воркер. Это сценарий для
проверенной конфигурации: контейнер Ubuntu с `apt`, Linux x86-64, RTX 3090 или
3090 Ti (24 ГБ VRAM), работающий драйвер NVIDIA, доступ к интернету и по крайней
мере 45 ГиБ свободного места. Наличие GPU проверяется отдельно от контейнера;
драйвер NVIDIA скрипт не меняет. Другие модели GPU пока не поддержаны сборкой.

На новой системе загрузятся проект, системные пакеты, Python, CUDA toolkit,
закреплённый stable-diffusion.cpp, три файла модели V10 и адаптер. Файлы весов
занимают около 19 ГиБ; для установки и сборки нужно дополнительное место.
Потребуется токен Civitai, если сервис запросит его: введите скрытым вводом,
не отправляйте в чат. Наличие и скорость источников не гарантируются. Скрипт
не оплачивает аренду и не создаёт GPU или облако.

Если облако потеряно и резервной копии нет, скрипт скачает веса снова и создаст
новые ключи доступа. Старые изображения, очередь, `.env` и пользовательские
данные восстановить автоматически невозможно. Если файлы и `.env` сохранены в
подключённом облаке, они используются повторно; платёжные условия и сохранность
при нулевом балансе нужно уточнить у QuData.

## Вариант 1: без облака

После SSH-подключения к **новой** чистой аренде под `root`, выполнить на сервере:

```bash
python3 -c "import urllib.request; urllib.request.urlretrieve('https://raw.githubusercontent.com/nutakoe27-commits/Farmilka/main/scripts/rent-setup.sh', '/tmp/photo-rent-setup.sh')" && bash /tmp/photo-rent-setup.sh --local
```

Всё будет установлено в `/opt`. У провайдера это может быть временное хранилище:
после удаления аренды файлы, результаты и ключи могут пропасть. Скрипт нельзя
использовать для восстановления старых результатов из уже удалённого контейнера.

## Вариант 2: с подключённым облаком

На экране создания новой аренды подключите существующее облако к `/workspace`.
Провайдер может требовать дополнительных настроек; сам скрипт облако не
подключает и не форматирует. После подключения по SSH выполните:

```bash
python3 -c "import urllib.request; urllib.request.urlretrieve('https://raw.githubusercontent.com/nutakoe27-commits/Farmilka/main/scripts/rent-setup.sh', '/tmp/photo-rent-setup.sh')" && bash /tmp/photo-rent-setup.sh --cloud
```

Скрипт откажется работать, если `/workspace` не отдельная точка монтирования.
На облаке создаются `/workspace/photo-service` и `/workspace/photo-toolchain`,
а `/opt/photo-service` и `/opt/photo-toolchain` будут ссылками на них. При новой
аренде того же совместимого шаблона и повторном подключении **сохранённого**
облака повторите команду `--cloud`: установленные файлы модели, адаптер, `.env`
и результаты будут использованы без повторного скачивания весов. На новой
машине системные пакеты при необходимости устанавливаются заново.

## Проверка и браузер

Установка может занять значительное время, включая скачивание и сборку CUDA.
Не закрывайте SSH до окончания. Если Civitai попросит токен, введите его
скрытым вводом. После строки `API and worker are ready` впервые проверьте
генерацию по тексту и с исходным фото: запуск процесса не гарантирует успешную
генерацию или качество на новой GPU. Ошибку и указанные пути к логам можно
прислать в чат; токены и содержимое `.env` присылать нельзя.

После запуска создайте SSH-туннель с Mac, используя **актуальные** хост и порт
из карточки новой аренды. В примерах ниже замените `НОВЫЙ_АДРЕС` и
`НОВЫЙ_ПОРТ` реальными значениями, а путь к ключу — если у вас другой ключ.

В первом терминале **на Mac**:

```bash
ssh -i "$HOME/.ssh/qudata_photo" -p НОВЫЙ_ПОРТ \
  -o ExitOnForwardFailure=yes -N -L 18000:127.0.0.1:8000 \
  root@НОВЫЙ_АДРЕС
```

Оставьте туннель открытым и откройте `http://127.0.0.1:18000`. В другом
терминале Mac скопируйте ключ API непосредственно в буфер обмена:

```bash
(
  set -o pipefail
  ssh -n -i "$HOME/.ssh/qudata_photo" -p НОВЫЙ_ПОРТ root@НОВЫЙ_АДРЕС \
    "cd /opt/photo-service && .venv/bin/python -c 'from dotenv import dotenv_values; print(dotenv_values(\".env\")[\"API_TOKEN\"], end=\"\")'" \
    | pbcopy
) && echo "Ключ скопирован"
```

Вставьте ключ в веб-интерфейс; файл `.env` и ключ в чат не отправляйте. При
установке на чистом диске ключи отличаются от прежних.

Скрипт отказывает в перезаписи чужих каталогов и не останавливает уже запущенный
воркер. После обрыва повторите ту же команду на той же аренде: готовые стадии
и успешно проверенные веса используются повторно. Если произошла ошибка,
сначала разберите её; не удаляйте каталоги и маркеры вручную наугад.
Команду запуска нужно выполнить после SSH-подключения: автоматический старт при
создании аренды QuData этим скриптом не настраивается. Если сервис уже запущен,
скрипт остановится, чтобы не создать второй воркер. Повторное использование
бинарников с облака требует совместимого шаблона ОС и драйвера; при ошибке
библиотек или CUDA их совместимость нужно проверить отдельно.
