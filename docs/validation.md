## Новый выбранный профиль: Qwen 2.1 Turbo / AtomicChat

Пользователь предоставил полный README репозитория
`AtomicChat/Qwen-Image-2.1-Turbo-Uncensored-GGUF`. Это изменённый **энкодер**
Qwen3-VL-8B с лицензией Apache 2.0. Он подключается как `--llm`; генератор
нужен отдельно из `AtomicChat/Qwen-Image-2.1-Turbo-GGUF`. По карточке автора,
изменения энкодера не повысили число изображённых сцен в его наборе из 45 запросов.

Подготовлены `qwen_gguf`, постоянный приватный процесс `sd-server`, загрузчик
четырёх компонентов, отдельный Docker-образ и Compose overlay, инструкция
`qwen-ru.md` с откатом. Выбраны авторские AD-Q4_K для генератора/энкодера,
F16 vision-проектор и VAE именно Qwen Image 2.1. README имена файлов известны;
их размеры и commit SHA должны быть получены через API при загрузке.

Проверено здесь:

- Все версии прежних зависимостей сохранены; extra `qwen` использует уже
  закреплённый huggingface-hub 2.4.0. Frozen lockfile проверен.
- Тесты разрешения компонентов разделяют энкодер и генератор, исключают
  незаметную подмену AD-Q4_K обычным Q4_K_M, закрепляют SHA и endpoint.
- Проверены SHA256, формат файлов, нехватка диска, прерванное обновление,
  анонимные загрузки без передачи HF_TOKEN и некорректные пути.
- Протокол native API для текста и фото проверен **с симуляцией backend**;
  таймаут/потеря ответа прекращают backend, готовность требует state=ready,
  запуск без CUDA отклоняется. Очередь и health принимают `qwen_gguf`.
- Из официальных исходников собраны `sd-server` и `sd-cli` CPU-варианта,
  revision `e239e4b0fd3de49834cec67031a44796ca465abc`, с его submodules.
  Сам build завершён успешно; компилятор выдавал предупреждения upstream.
- Реальный C++ процесс запущен без весов: status/capabilities/recipes API
  ответили, встроенное Turbo-расписание сверено с настройкой клиента,
  запрос генерации без загруженной модели корректно получил HTTP 503.
- Docker API-образ собран; Compose-конфигурации базового GPU, LoRA и Qwen проходят проверку.
- Полный Docker smoke API + demo-worker прошёл: `engine=mock`, 512×512,
  reference=False, 2.2 секунды. Это заглушка для проверки сервиса, не Qwen.

В этой среде нет GPU. CUDA-сборка `Dockerfile.qwen-gguf`, загрузка AtomicChat
весов, CUDA-ядра, настоящие генерация/редактирование, VRAM и скорость **не проверены**.
Готовность C++ процесса без весов и симуляция HTTP не доказывают работу модели.
Карточки/metadata PirateFace и HF из Codex блокирует CONNECT 403 прокси;
настоящие SHA и доступ к файлам ещё нужно проверить на QuData. Это не
установленная ошибка токена и не повод запрашивать секрет в чат.

Официальный README и LICENSE Qwen Image 2.1 прочитаны через GitHub;
Turbo-генератор имеет Qwen Research License с отдельной коммерческой лицензией.
Метаданные Apache 2.0 выбранного энкодера не заменяют лицензию генератора.
На прежнем сервере пользователя был проверен Klein; пользователь сообщил,
что отключал сервер на ночь и арендует заново. Новый адрес, сохранность диска
и состояние сервисов пока не проверены. Код Qwen самостоятельно на QuData
не установлен. В `qwen-ru.md` добавлен порядок установки для чистой VM,
включая сборку отсутствующей CUDA/Python-базы без загрузки весов Klein.

## Подтверждено на GPU-сервере пользователя до переезда

Это отдельная арендованная QuData VM; GPU не является частью облачной CPU-среды Codex.
Данные получены из команд и изображений, которые пользователь прислал в чат:

- RTX 3090 Ti, 23.5 GiB VRAM; драйвер 580.178.04.
- PyTorch 2.10.0+cu128; CUDA bfloat16 matrix operation: PASS в GPU-контейнере.
- Klein 4B скачан и загружен; воркер сообщил `Engine ready: flux`.
- Настоящий text-to-image 512×512: `PASS engine=flux`, полный запрос 32.5 секунды.
  Пользователь открыл результат: красный чайник у окна на деревянном столе.
- Фото + инструкция проверены полученным изображением: чайник стал синим,
  основная композиция сохранилась. Время этого запроса не зафиксировано.
- Веб-интерфейс открыт на Mac через личный SSH-туннель; заполнение ключа и
  отдельный запуск генерации из браузера ещё не подтверждены.
- Первичный экспорт GPU-образа был длительным. Экспорт без сжатия завершился:
  445.3 секунды экспорт слоёв, 73.7 секунды unpack, всего этапа 519.3 секунды.
  Это наблюдение не доказывает единственную причину предыдущей задержки.

## Новый режим Heartsync: пока не проверен на реальных весах

По API Hugging Face, присланному пользователем: это `lora.safetensors`,
687476088 байт, revision `328160f16bc4072cf2bb7ee162d77f3b9b5f786c`,
для базовой `black-forest-labs/FLUX.1-dev`. В карточке LoRA указана OpenRAIL-M;
база имеет отдельную Non-Commercial License, проверенную в официальном репозитории BFL.

Код `flux_lora`, загрузчик, расширение GPU-образа, проба NF4/PEFT и инструкция
возврата к Klein подготовлены. Фактический импорт GPU-зависимостей, загрузка
адаптера, потребление памяти, скорость и качество этого режима ещё не подтверждены.
Этот вариант больше не выбран для текущего перехода; пользователь переключился
на Qwen. Доступ к FLUX.1-dev для Qwen не требуется. Токен в чат не запрашивается.

Следующие обязательные проверки перечислены в `heartsync-ru.md`: доступ аккаунта,
NF4 + LoRA CUDA probe, загрузка базы и адаптера, готовность нового воркера,
оба smoke с `--expect-engine flux_lora`, просмотр изображений и возврат при сбое.
Успешные CPU-тесты не заменяют эти испытания.
