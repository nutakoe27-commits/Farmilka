# Проверки текущей облачной среды

Дата: 29 октября 2026, Europe/Moscow. Новый проект: `/workspace/new-project`,
ветка `main`. Существующий Farmilka не использовался для реализации.

## Выполнено

- Python 3.12; `uv lock` создал lockfile; `uv lock --check` подтверждает его
  соответствие pyproject. CPU-зависимости установлены через `uv sync --frozen`.
- Повторный `scripts/bootstrap.sh` сохраняет окружение; повторный
  `scripts/init_env.py` сохраняет уже существующий `.env` и ключи, права — 0600.
- **14 тестов pytest прошли**: text/reference → очередь → воркер → PNG,
  сохранение после рестарта API, разделение ключей, ограничение загрузки,
  нормализация фото, ограничение очереди, конкурентная выдача, устаревшие
  аренды, ограничение повторных попыток и передача ошибки нехватки памяти.
- Раннер выдал одно предупреждение о будущей замене HTTPX в TestClient
  Starlette; тесты выполнены и завершились успешно.
- Проверены 10 наборов перевода, по 36 строк в каждом, и наличие переводов
  для элементов HTML; синтаксис frontend JavaScript корректен.
- API и mock-воркер реально запущены как отдельные процессы. Сквозные
  `scripts/smoke.py` с текстом и с reference image получили PNG 512×512.
- CPU Docker-образ собран; Docker Compose запустил API и отдельный demo-worker.
  Те же две функциональные проверки через HTTP получили PNG 512×512.
- Оба профиля Compose (`demo`, `gpu`) проходят `config --quiet`.

Успех mock означает готовность транспорта, очереди и хранения, **не качество
или работоспособность GPU-inference**. В mock-файлах явно написано DEMO.
Автоматической проверки отображения UI в настоящем браузере не проводилось.

## Исправления среды при проверке Docker

Docker builder не разрешал имя предоставленного средой прокси. Сборка прошла
после передачи существующего прокси, его DNS-сопоставления и штатного CA bundle.
Это воспроизводит `scripts/build_image.py`. TLS и хэши lockfile не отключались;
CA передавался через временный BuildKit secret. Права файлов в образе
нормализованы через владельца 10001, приложение работает без root.

## Ещё не проверено

- Аренда и доступность конкретного GPU-предложения, текущие цены Runpod/Vast.ai.
  Страницы провайдеров вернули CONNECT 403 от сетевого прокси.
- Скачивание весов Hugging Face, сборка GPU-образа, установка CUDA-зависимостей,
  загрузка модели, реальная text-to-image и reference-image генерация.
- Время, VRAM/RAM, себестоимость и качество модели на конкретной GPU и языках.
- Публичный деплой, домен, HTTPS, аккаунты, платежи и география доступности.
- Публикация снимка среды и восстановление проекта в новой задаче.

GPU-зависимости разрешены и зафиксированы в lockfile, но в CPU-среду не
устанавливались: это не заменяет испытание на NVIDIA GPU.

Сетевые домены для провайдеров и Hugging Face сохранены в черновике настроек.
Сохранение черновика само по себе не применяет сетевые правила и не публикует
среду. Сценарий установки и инструкция старта сохраняются отдельно через
инструмент настройки среды; статус их сохранения сообщается в чате.

## Следующая обязательная проверка

После выбора и аренды GPU выполнить вариант A или B из `deploy-ru.md`,
`gpu_probe.py` и **обе** команды `smoke.py --expect-engine flux`. После этого
вручную проверить полученные фотографии и измерить память и скорость.
До выполнения этих шагов GPU-развёртывание считается неподтверждённым.
