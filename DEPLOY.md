# Деплой Farmilka на сервер

## Что нужно от вас

1. **VPS с Ubuntu 22.04 / 24.04.** Хватит самого дешёвого тарифа: 1 vCPU, 1–2 ГБ RAM
   (до ~40 игроков онлайн). Примеры: Hetzner (~€4/мес), Timeweb, Selectel, beget и т.п.
2. **Открытые порты**: 22 (SSH), 80 (HTTP), 443 (HTTPS). Обычно открыты по умолчанию;
   если у хостера есть встроенный файрвол — откройте их в панели.
3. **(Опционально, но рекомендую) Домен** с A-записью, указывающей на IP вашего VPS.
   С доменом Caddy автоматически получит сертификат Let's Encrypt, и игра будет
   работать по HTTPS/WSS. Без домена — игра доступна по `http://IP-адрес`.

Больше ничего: база данных встроенная (SQLite), всё остальное поднимает Docker.

## Первый запуск (≈10 минут)

Подключитесь к VPS по SSH и выполните:

```bash
# 1. Установить Docker
curl -fsSL https://get.docker.com | sh

# 2. Склонировать репозиторий
git clone https://github.com/nutakoe27-commits/Farmilka.git
cd Farmilka

# 3. Задать токен админки
cp .env.example .env
nano .env        # замените change-me на свой длинный случайный токен

# 4. (Если есть домен) вписать его в Caddyfile
nano Caddyfile   # закомментируйте блок ":80", раскомментируйте блок с доменом

# 5. Собрать и запустить
docker compose up -d --build
```

Готово. Игра доступна на `http://ВАШ_IP` (или `https://ваш-домен.ру`).
Дашборд баланса: `http://ВАШ_IP/admin/stats?token=ВАШ_ТОКЕН`.

## Обновление игры

```bash
cd Farmilka
git pull
docker compose up -d --build
```

Игроки при перезапуске будут отключены на ~30 секунд (прогресс сессии в памяти,
постройки/деньги обнуляются — аккаунтов в MVP нет).

## Настройка баланса — без пересборки и рестарта

Все игровые числа лежат в **`balance/balance.json`** (урон и цены оружия, HP и награды
мобов/босса, доход построек, экономика смерти и т.д.). Файл смонтирован в контейнер
и перечитывается автоматически при сохранении:

```bash
nano balance/balance.json   # правите числа, сохраняете — применилось на живом сервере
```

Если файл сломан (невалидный JSON) — сервер пишет ошибку в лог и продолжает работать
на старом конфиге. Принудительная перезагрузка: `curl -X POST "http://localhost/admin/reload?token=ВАШ_ТОКЕН"`.

### Как понять, что нерфить

Откройте `/admin/stats?token=...` — там таблицы по собранной телеметрии:

- **Баланс оружия**: K/D по каждому оружию, доля PvP-убийств, урон, средняя
  дистанция убийства. Оружие с K/D сильно выше остальных — кандидат на нерф.
- **Доход по источникам** (мобы / босс / постройки / лут / рейды) в пересчёте
  на игро-час — видно, если, например, фермы дают больше, чем весь PvE.
- **Боссы**: сколько убито, сколько игроков участвует.
- **Смерти по причинам** и **длина сессий** — если все умирают от одного и уходят
  через 5 минут, вы знаете, куда смотреть.

## Бэкапы

Вся статистика — один файл SQLite:

```bash
mkdir -p backups && cp data/game.db backups/game-$(date +%F).db
```

## Полезные команды

```bash
docker compose logs -f game     # лог игрового сервера
docker compose logs -f caddy    # лог прокси/сертификатов
docker compose restart game     # перезапуск только игры
docker compose down             # полная остановка
```

## Проверка после деплоя

1. Откройте игру с телефона (мобильный интернет = реальная задержка) — движение
   должно быть плавным.
2. Убейте пару мобов, затем откройте `/admin/stats` — в таблицах появятся данные.
3. Поменяйте `damage` у меча в `balance/balance.json` — урон в игре изменится
   сразу, без рестарта.

## Нагрузочный тест (по желанию)

С локальной машины можно натравить ботов на сервер:

```bash
npm install
npm run bots -w server -- --n 30 --url ws://ВАШ_IP/ws --minutes 5
```

В логе сервера (`docker compose logs -f game`) не должно быть предупреждений
`slow tick`.
