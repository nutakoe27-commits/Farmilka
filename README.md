# Photo Service — новый проект

Закрытый пилот сервиса генерации фото на своей или арендованной NVIDIA GPU.
Рабочая ветка — **только `main`**. Рабочий каталог — `/workspace/new-project`;
прежний каталог `/workspace/Farmilka` для разработки не используется.

**Пошаговый запуск, выбор аренды и расчёт бюджета:** [docs/deploy-ru.md](docs/deploy-ru.md).

## Что реализовано

- Текст → изображение и фото + инструкция → изображение.
- FastAPI, постоянная очередь SQLite, отдельный GPU-воркер, повторное получение
  задания после потери воркера, ограничение очереди.
- Модель `black-forest-labs/FLUX.2-klein-4B`, четыре шага, Apache 2.0.
- Интерфейс: русский, английский, испанский, немецкий, французский,
  португальский, турецкий, китайский, японский и арабский; RTL для арабского.
- Раздельные ключи клиента и воркера; оригиналы и результаты не публикуются
  как общедоступные статические файлы. EXIF удаляется при загрузке.
- Режим `mock` для проверки сервиса без GPU. Он создаёт **тестовую заглушку**.
  Режим `flux` запускает настоящую модель локально на GPU.

Это основа сервера генерации, а не запущенная публичная коммерческая платформа.
Пока нет пользовательских аккаунтов, изоляции данных между клиентами, оплаты,
учёта кредитов и видео. Общий API-ключ предназначен для закрытого пилота.
Языки интерфейса не означают проверенное качество промптов на всех языках мира.

## Быстрая локальная проверка без GPU

В корне проекта:

```bash
sh scripts/bootstrap.sh
.venv/bin/pytest -q
.venv/bin/uvicorn photo_service.api:create_app --factory --host 127.0.0.1 --port 8000 --no-access-log
```

Во втором терминале из того же каталога:

```bash
.venv/bin/python -m photo_service.worker
```

В третьем:

```bash
.venv/bin/python scripts/smoke.py --expect-engine mock
```

Демонстрационный вариант через Docker:

```bash
python3 scripts/init_env.py
docker compose --profile demo up -d --build
docker compose logs --tail 100 api demo-worker
```

GPU-запуск, работа из Pod и SSH-туннель описаны в инструкции. Облачная среда
онбординга не предоставляет публичное превью локального сайта.

## Архитектура

```text
Браузер → API + SQLite + файлы ← GPU-воркер → локальные веса FLUX
                  ↑                 |
                  └── PNG-результат ─┘
```

Один API-процесс с SQLite достаточен для первого закрытого пилота. Воркер
сам забирает задания по HTTP; входящий публичный порт на GPU не требуется.
Для отдельного GPU-сервера задаются `CONTROL_URL` и `WORKER_TOKEN`; публичное
соединение с API должно использовать HTTPS. Модель получает исходное фото
как reference image: сохранение лица, композиции и всех деталей не гарантировано.

Чтобы добавить видео, потребуется новый движок, формат задания и хранилище
результатов; текущий код не заявляет поддержку видео.
